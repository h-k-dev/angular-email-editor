Styling

Every visual aspect resolves through a three-step chain, at point of use: --email-* → --mat-sys-* → a hardcoded fallback. Set any token on :root, on a container, or on the element itself — with a Material M3 theme present (like this example app) the middle step already carries light and dark, so most hosts set nothing at all. The exports behind these surfaces are on the API page.

Where the styles live

ProseMirror creates the editable DOM at runtime, outside Angular’s emulated view encapsulation — so the editor surface is styled globally, and every rule scopes to .aee-editor, the identity class the library stamps on its own editable roots. Never style bare .ProseMirror: a ProseMirror instance the host runs for anything else has to be left alone. The composer’s own chrome (menus, pickers, preview) is component-scoped as usual.

Inside an Angular Material form field

The address input is a control, never its own row — in a Material app the row is a mat-form-field. Opt in per field with emailMatFormField (angular-email-editor/material, the one entry that imports Material): the label floats, mat-error shows once the field is touched and invalid, hint and error are read out, and a click anywhere in the field puts the caret in.
