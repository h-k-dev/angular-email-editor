Styling

Every colour, corner and size in the editor is a custom property you can override. Most hosts with a Material theme set none at all. The exports behind these surfaces are on the API page.

How theming works

Each token resolves in three steps, at the point of use:

--email-*--mat-sys-*a hardcoded fallback

  • Set a token on :root, on a container, or on the element itself.
  • With a Material M3 theme present — like this app — the middle step already carries light and dark, so most hosts set nothing.
  • The fallback keeps the editor usable with no theme at all.

Where the styles live

ProseMirror creates the editable DOM at runtime, outside Angular’s view encapsulation, so the editor surface is styled globally. Every rule scopes to .aee-editor, the class the library stamps on its own editable roots.

  • Never style bare .ProseMirror: a ProseMirror instance the host runs for anything else must be left alone.
  • The composer’s own chrome — menus, pickers, preview — is component-scoped as usual.

Material form field

The address input is a control, never its own row — in a Material app the row is a mat-form-field.

Opt in per field with emailMatFormField from @h-k-dev/angular-email-editor/material, the one entry point that imports Material:

  • the label floats;
  • mat-error shows once the field is touched and invalid;
  • hint and error are read out;
  • a click anywhere in the field puts the caret in.
